# Running under T3 Code

Part of the [`running-unattended`](SKILL.md) skill.
A coordinator in a T3 Code thread (`T3CODE_THREAD_ID` set, observed 2026-11-22) dispatches through T3's orchestrator tools.
This table replaces the [`orca orchestration` flags](coordinator.md#orca-orchestration-flags), the [dsh dispatch steps](coordinator.md#dispatching-a-dsh-worker), and the Orca steps in [`loop-and-bounds.md`](loop-and-bounds.md): the `worker-read` start check, `worker_done`, the "stopped without reporting" escalation and closing terminals.
The rest of the skill holds.
The machine's T3 settings (worktree location, cleanup, Full access) are in [`harness-setup.md` § T3 Code](../../../docs/harness-setup.md#t3-code).

| Need | Tool call |
|---|---|
| Start the coordinator | The current session's model in **Full access**, in the primary checkout. Children inherit the mode and cannot exceed it, and T3 routes a child's questions to the coordinator but not its approval prompts, so a narrower mode stalls items. |
| Discover providers | Call `orchestrator_capabilities` once per thread before the first `delegate_task` to read enabled providers (`claudeAgent`, `antigravity`, `dsh`, `codex`), exact model IDs and option keys; map labels, `wide` and starting efforts through [`models.md`](../../../docs/harness/models.md) and [`harness.md`](../../../docs/harness.md#policy-any-agent). |
| Start an implementer | `delegate_task` with the brief as `task`, `isolation:"worktree"`, `role:"implementation"`, `mode:"async"`, `title:"<issue>-<slug>"` and `target:{providerInstanceId, model, options}` picked from enabled providers via [`models.md`](../../../docs/harness/models.md) and the issue's labels ([`SKILL.md`](SKILL.md#concurrency-and-models)), passing that harness's starting effort in `options` (important on Codex, where `Sol`/`Astra` default to `low`). Log its `taskId` and `childThreadId`. |
| Start a planner | `delegate_task` with the [Planner brief](worker-brief.md#planner-brief) as `task`, `isolation:"shared"`, `role:"research"`, `mode:"async"`, `title:"plan-<issue>-<slug>"` and an enabled `heavy` model + starting effort from [`models.md`](../../../docs/harness/models.md). Log its `taskId` and `childThreadId`. |
| Branch | The worker branches `neilsh/<issue>-<slug>` from `origin/main` ([`loop-and-bounds.md`](loop-and-bounds.md#implementing-an-issue-and-bounding-rounds) step 2), leaving T3's `t3/` branch unused. |
| Worker report | Its final reply. A completion wakes the coordinator; then read it once with `task_status`, never on a running task. |
| Answer a worker's question | `t3_pending_request` on its `childThreadId`. |
| Send a fix brief | `t3_thread_send` to the implementer's `childThreadId` with `freshContext:true`: a fresh session in the same worktree. It returns a new `taskId`; log it and read the fix report from that task, since the first task's result never changes. |
| Review | Claude reviewers stay native subagents when the coordinator runs on Claude; non-Claude or cross-provider reviews (Antigravity `Orchestrator (Neon)`, Codex `Astra`, or Claude from another coordinator) are a new `delegate_task` per round with `target:{providerInstanceId, model, options}` from [`models.md`](../../../docs/harness/models.md), `role:"review"` and the default `isolation:"shared"`, working in the `review-worktree` path its brief names. |
| Rule 5 push | `t3_thread_read` on the `childThreadId` gives the `worktreePath` to review at and push from. |
| PR commands | The `gh` and `mise` commands this skill names, not T3's `pull_request_*` tools: the merge bar is built on them. |
| CodeRabbit timer | `schedule_task` with `{type:"once", runAt:"<request time + 20 min>"}` and `bindToCurrentThread:true`. |
| Restart at about 100k tokens | `t3_thread_send` to the coordinator's own thread with `freshContext:true` and "Read the `running-unattended` skill and `build/scratch/run-state.md`; resume at Next action", then end the turn: a fresh-context send queues and never steers. Workers should keep reporting to the same thread; the first restart confirms it. If T3 refuses a send to its own thread, wait until no worker is in flight, then `t3_thread_launch` a successor with the same model and message. |
| Retire worktrees | T3's after-merge cleanup policy, run hourly; T3 worktrees are outside `mise run reap`'s pool. |

T3 workflows ([a Labs feature, off by default](https://github.com/pingdotgg/t3code/blob/main/docs/user/workflows.md#turn-on-workflows)) are not used.
Whoever first uses a line successfully adds what it taught to this table in their PR.
