# Quality gate and CI

The gate is `mise run check`: one script ([gate.py](../python/scripts/gate.py), [ADR 0014](adr/0014-the-gate-is-one-ordered-script.md) and [ADR 0016](adr/0016-the-gate-runs-independent-lanes.md)) that prints one line per step, quotes the tail of every failing step, writes the whole output to `target/check.log`, and ends with PASS or FAIL. Independent steps run as concurrent lanes — cargo steps that share a target directory stay in one ordered lane, everything else runs beside them — so one run also reports every failing step, not only the first. `mise run check-rust` and `mise run check-py` run the same step list for one language, and `mise run check-docs` runs only the documentation tests (`test-py-docs`, the modules marked `docs`). A failing run's last line says what to run next: `fix: mise run fix` when a format or `lint-py` step failed, and `re-run: mise run check-rust` / `check-py` / `check-docs` for the half that failed (a scoped run never names itself).

`mise run check` runs only what the branch touches ([ADR 0038](adr/0038-the-local-gate-runs-what-a-change-touches.md)). It reads the paths changed since the merge base with `origin/main` (with `main` when there is no `origin/main`), untracked files included, and sorts each one: `tests/fixtures/**` is other; `crates/**`, `Cargo.toml`, `Cargo.lock`, `deny.toml` and `research/parity/report-fields.md` (a Rust test reads it) are Rust; `*.py`, `pyproject.toml` and `uv.lock` are Python; `*.md` and `*.ksy` are docs; anything else is other. Rust paths run the Rust half, Python paths the Python half, and a run without the Python half adds the docs half. It runs the full gate, and prints why, on `mise run check -- --full`, when `CI` is set, for any other path, when nothing changed, and when git cannot say (neither `origin/main` nor `main`); `-- --base <ref>` counts from another branch. The gate prints its scope and the paths behind it first. CI's `quality` job runs `mise run check` with `CI` set, so the full gate, except on a docs-only pull request, where it calls `check-docs` directly ([ADR 0047](adr/0047-ci-scopes-a-docs-only-pull-request.md)). Individual tasks:

The pre-commit hook is installed by `mise run init` (`core.hooksPath = .githooks`) and holds no command of its own: it runs `mise run pre-commit`, which is [prek](https://github.com/j178/prek) over [`prek.toml`](../prek.toml) ([ADR 0026](adr/0026-commit-hooks-run-the-gates-own-tasks.md)). prek sets unstaged edits aside first, so the hooks check what is being committed. Its local hooks are leaf tasks of `mise.toml` — `test-docs` and `check-work-frozen` (a file added to a frozen work folder, or its outcome changed) on every commit, `fmt-check-rust` when Rust is staged, `fmt-check-py` and `lint-py` when Python is — so they cannot drift from the gate the way the deleted `.pre-commit-config.yaml` did; the rest are prek built-ins (large files, Windows-illegal names, case conflicts, merge conflicts, TOML and YAML syntax, private keys, trailing whitespace and final newlines, and others listed in ADR 0026). No hook changes what is committed: `mise run fix` (or `mise run fmt`, which only formats) fixes a format failure. It catches what commits most often broke (conflict markers left by a rebase, broken doc links) in seconds; it does not replace `mise run check` before a commit, and CI runs the built-ins on every pull request and push to `main`. Setting `core.hooksPath` turns off untracked hooks in `.git/hooks`, so `.githooks/pre-commit` and `.githooks/pre-push` chain to one there if present, and `init` names any other it turns off. `git commit --no-verify` skips the hook once.

The gate's lanes build the check profile into `target/check` and the no-default-features matrix into `target/matrix`, so those builds can run beside the `target/` build instead of waiting on its lock. All three directories sit under `target/`, which `.gitignore`, ruff's exclude, the recursive walkers and `mise run clean` already cover.

CI ([`.github/workflows/ci.yml`](../.github/workflows/ci.yml)) invokes the mise tasks instead of restating them. A pull request that is not docs-only (below) runs the full `mise run check` gate on Ubuntu, with Mesa's lavapipe installed and `STUNT_REQUIRE_GPU=1` set so a missing adapter fails the GPU tests instead of skipping them ([ADR 0006](adr/0006-ci-renders-on-lavapipe.md)), and `check-windows-smoke` on Windows for the tests that can behave differently there. Windows gets a smoke test rather than the whole gate on pull requests because every Windows-only behaviour in this repository lives in the Python tree — `crates/` has no `cfg(windows)` — while a warm Windows Rust build costs about nine minutes. Pushes to `main` run the full `check-windows` too (format, lint, typecheck and both test suites; GPU tests skip without a driver), and `workflow_dispatch` runs the jobs a push to `main` runs, on any branch. A separate job checks the declared MSRV (`1.100`), and a `cargo deny` job enforces the dependency policy. The cargo cache falls back to the newest previous lockfile through `restore-keys`, so a dependency bump rebuilds a delta instead of the whole workspace — a cold gate run measured 10m40 against 4m19 warm. Each job installs only the toolchain its task list uses (`rust`, `python`, `uv`, and Java with the Kaitai compiler where `test-py` runs), because `mise run` otherwise installs every tool `mise.toml` declares before its first task — compiling `cargo-deny` and `cargo-llvm-cov` from source and downloading DOSBox inside the gate — so the jobs that use mise set `MISE_AUTO_INSTALL=false`. Corpus- and emulator-dependent tasks stay local. A docs-only pull request, one whose changed paths are all docs by the gate's own classifier (`gate.py scope`, read by the `scope` job), runs less ([ADR 0047](adr/0047-ci-scopes-a-docs-only-pull-request.md)): `quality` runs `mise run check-docs` without lavapipe, Rust or the cargo cache, and `windows-smoke`, `msrv` and `deny` skip; the workflow is set up so that if `scope` fails, they all run. Pushes to `main` stay full, so a failure only the full gate catches shows there after the merge. A ruleset on `main` requires five checks by display name — `Quality gate (ubuntu)`, `Windows smoke`, `MSRV check`, `Dependency policy` and `PR title` — and blocks force pushes and deletion; repository admins may bypass it to push straight to `main`. GitHub documents that a job skipped by its own `if:` reports as passing, while a workflow-level `paths:` filter would leave a required check pending, so the scoping lives in job conditions, and those display names must not change. Neither the skip nor the failed-`scope` path has run in this repository yet (ADR 0047). The full Windows gate runs only on pushes to `main` and manual runs, so it is not a required check. A separate workflow, [`.github/workflows/pr-title.yml`](../.github/workflows/pr-title.yml), checks the pull request's title as a Conventional Commit (job `PR title`). Actions are pinned to commit SHAs with the release in a trailing comment, and Renovate bumps them ([Dependency updates](toolchain.md#dependency-updates)).

## GPU tests

The `gpu` test binary (`crates/stunt-render/tests/gpu/`, kept apart from the merged `it` binary so the hang-rate loop can run it alone) exercises the Vulkan/DX12/GL loader and vendor driver locks, and a wedge there leaves a plain `cargo test` waiting forever without printing a result; [run it with the per-test deadline](howto/run-the-gpu-tests.md). Every test in it wraps its body in `common::gpu_test`, which holds one process-wide lock and runs the body on a thread it joins before releasing the lock; opening a renderer outside it panics. The join is the point (`[Bounded Observation]`, one NVIDIA RTX 4070 laptop): a thread that had used NVIDIA's OpenGL driver (`nvoglv64.dll`, reached through the software-only adapter's all-backends instance, or a dropped GL instance's `wgpu-hal WGL Instance Thread`) and exited after the lock was released ran its `DllMain` detach holding the loader lock, and deadlocked against the next test's Vulkan `request_device` loading a DLL (12 hangs in 150 runs without the join, none in 200 with it). For the same reason a test that builds its own `wgpu::Instance` leaves out `Backends::GL`: wgpu ends the WGL thread after the instance drops, outside any lock. _Source: [2026-11-07: GPU tests hang on an NVIDIA laptop](../work/2026-11/distill-development/journal.md#2026-11-07-gpu-tests-hang-on-an-nvidia-laptop)._

## A PermissionError on Windows

On this machine's Dev Drive (`E:`, ReFS), the gate now and then fails a Python test with `PermissionError: [Errno 13] Permission denied` or `[WinError 5] Access is denied` on a file the test does not hold, and a rerun passes. The test does not matter: it has been a tracked file untouched for an hour (`manifests/all/*.toml`, `python/scripts/*.py`), a file or directory under the pytest basetemp, or a scratch repository's `.git/config` read just after `git config` wrote it. A plain `git switch -c` outside pytest was once refused the checkout's `.git/config` the same way. Session transcripts hold 43 such minutes between 2026-10-29 and 2026-11-09, across many worktrees, under both `mise run check` and `mise run regate` (`[Bounded Observation]`).

What holds the file is not yet named. Ruled out: `regate`'s checkout racing the tests (git finishes the checkout before the gate starts, no `post-checkout` hook runs, and the plain gate fails the same way), the basetemp pruning in `tests/pytest_helpers.py` (it keeps the three runs with the newest UTC-stamped names, so it deletes a live run only if three or more later runs start in the same checkout while it runs, and one gate starts two; and the sampled tracked files have one link each), a gate in another worktree (none was running at the 2026-11-09 failures), a sandbox ACL (the worktree carries only inherited ACEs, and the token no restricted SID), the search indexer (Windows Search returned no indexed items under `E:` when queried on 2026-11-09), and ReFS keeping a deleted file's name (on the Dev Drive, a file deleted while another handle had it open with `FILE_SHARE_DELETE` lost its name at once, as on NTFS). It did not recur on demand: 4 full gates, 9 `regate` gates and 4 pairs of concurrent pytest runs passed while a watcher polled 282 files for a refused open, and in another worktree 6 full gates and 9 concurrent `test-py` plus `test-py-docs` runs passed too. Defender's operational log shows nothing at either failure, but its exclusions and scan activity need admin to read, so a scanner holding a file is neither confirmed nor ruled out. Windows Security Center lists no antivirus besides Defender, but it does not list every filter driver, such as backup or sync software.

The pruning did have a defect of its own, now fixed. `shutil.rmtree(ignore_errors=True)` could not delete git's read-only object files, so every run's basetemp stayed behind (102 in one worktree), and every xdist worker walked all of them again at start-up. The prune now clears the read-only bit, and only the controller runs it.

When a test fails on a `PermissionError`, `tests/conftest.py` asks the Restart Manager which processes hold each path the error names and adds a `file holders` section to the failure report. It sees a holder only while it still holds the file, and a file pending delete shows as held by no process. Copy that section onto [#260](https://github.com/neilsh/stunt-reel/issues/260) before rerunning. _Source: [#357](https://github.com/neilsh/stunt-reel/issues/357)._

## Tests that failed under concurrent gates

Seven Python tests failed now and then while two or three gates ran at once on this machine, and passed when rerun alone ([#571](https://github.com/neilsh/stunt-reel/issues/571)). One cause is reproduced and fixed: elapsed-time bounds in `tests/test_process_tree.py`. With 32 busy-loop processes beside a `pytest -n auto` run of the seven modules, an interrupted child took 45.7 s to end against a 20 s bound, and a command that exits at once, given a 30 s timeout, was killed on that timeout. Those tests now assert what a kill leaves instead of how long it took: a nonzero exit code, or a grandchild gone while its own sleep would still run. With the kill disabled, a grandchild test that checked after the child's `with` block still passed on Windows: that block did not exit until the grandchild's own sleep ended, so the grandchild was gone by then (`[Bounded Observation]`, one run). The test now checks before that block closes the pipe. A test that bounds a wait does it as a deadline on a condition, long enough not to matter under load (`_GONE_WITHIN`), never as a claim about speed.

The other six did not fail again. 12 full `pytest -n auto` runs (three at once, beside 8 busy-loop processes) and three pairs of concurrent `mise run check -- --full` gates, run on 2026-11-15 and 2026-11-16, all passed. What survives of the original failures (`[Bounded Observation]`, session transcripts):

- `test_gate_plan` (`test_changed_paths_counts_from_origin_main_past_a_stale_local_main`): `git add landed.md` exited 128 in the test's scratch repository, and its stderr was not shown. The `_git` helpers in `test_gate_plan.py` and `test_work_frozen.py` now quote git's stderr, so the next failure names its cause. A refused file, as in [A PermissionError on Windows](#a-permissionerror-on-windows), would fit, but that is not confirmed.
- The formats catalog: no message survives from this run. An earlier failure (2026-10-31) was the Kaitai compiler's JVM crashing at start-up (`guarantee(name != nullptr) failed: jimage file name is null`).
- `test_tac_capture` (`test_capture_reports_windows_with_no_usable_page`), `test_target_seed` (`[ambiguous-build]`), `test_capture_run` (`test_a_stall_on_patch3_…[error0-…]`) and `test_work_frozen`: only their names survive. Each writes its files under its own `tmp_path` (the branch check in `test_work_frozen` also reads the repository at `REPO_ROOT`), none of the named tests has a timeout, and none failed under the CPU load of the runs above. `test_target_seed`'s fixtures do stamp file times from `time.time()`, some only 1 to 10 s apart.

## `stunt-core` test kinds

`stunt-core` tests come in three kinds. Named single inputs with exact expected results go in the `*_spec.rs` and `*_test.rs` files. Never-panics checks over random or mutated bytes are the fixed-seed `XorShift64` loops in the `*_fuzz.rs` files. A property that must hold for every valid input goes in a `*_props.rs` file, or in a `props` module beside the crate-private code it tests: write then read gives back the input, two implementations of one rotation agree, sampling at a keyframe returns that keyframe. These use [proptest](https://docs.rs/proptest), which builds constrained inputs (unit quaternions, timelines with same-tick slices) from composable strategies and shrinks a failure to a minimal case. Each runs 256 cases from a fixed seed, so the gate sees the same cases every run; setting `PROPTEST_CASES=10000` or `PROPTEST_RNG_SEED=<n>` for a `mise run test-rust` explores further without an edit. No regression files are written: when a property fails, add its shrunk input to the matching spec file as a named test, then fix the code or the property.
