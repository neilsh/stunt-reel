# Journal: generator model frame

## 2026-11-11: the raw-coordinate generators read statically

- **Question**: What corner order and coordinate signs do the `OP_IPG` types 2, 4, 6 and 8, `OP_SPHERE`, `OP_PERFDISK` and `OP_VEC` handlers of `PLAYONE.EXE` write, and does `vm.rs` match them ([#272](https://github.com/neilsh/stunt-reel/issues/272))?
- **Method**: `mise run vm-handler` for `0x0063`, `0x00FC`, `0x010E` and `0x004B`, then `mise run disasm` over the `OP_IPG` subtype handlers (image `0xB41E..0xB61D`), the bucket walker `0x1B75..0x1BE6`, the row transform `0x88FB`, `OP_SPHERE` (`0x9DB5..0x9E28`), `OP_PERFDISK` (`0xA040..0xA2BC`) and the dispatch slots around `0x8288`, on the unpatched build at `70cf324`. A throwaway `stunt-core` example walked every unique `0x000C`-magic model under the data root's `corpus/` with `trace_sod` and counted the steps of each opcode, then dumped `SCENERY1.RES` entry `0013` (a type-8 user). A second throwaway example tallied the winding of decoded stock triangles against each shape's centroid.
- **Result**: Type 2 (`0xB41E`) stores raw `(+a, 0, −b)`, `(+a, 0, +b)`, `(−a, 0, +b)`, `(−a, 0, −b)` in `reg + 0..3`, the cube's top-face order; `vm.rs` already wrote it turned. Type 8 (`0xB4B5`) stores raw `(+a, +b, 0)`, `(−a, +b, 0)`, `(−a, −b, 0)`, `(+a, −b, 0)`; `vm.rs` had corners 1 and 3 swapped, the reverse winding. Type 4 (`0xB54C`) reads one word and, when `DGROUP:0x2346 + w` is nonzero, saves the 23-word block at `work:0x806E`, draws the pending-object list through `0x1B75` and restores the block; no register written. Type 6 (`0xB58D`) reads no stream word: it writes registers 4..10 as `M · (x_i, 0, 2(i + 1)) >> shift` plus the `BX`, `DX`, `BP` it was entered with (`BX` = 6 from the dispatcher), `x_i` from the sine table and the global tick `DGROUP:0x22B8`; `vm.rs` read two words. `OP_SPHERE` (`0x9DB5`) reads `reg, radius` and fills a screen circle of radius `radius · [0x8070] / (z + [0x8088])` at the register's projected point (`0x8010`), or one pixel when that rounds to 0; it writes no register and tests no facing. `OP_PERFDISK` (`0xA040`, operands read by `0xA08E`) reads `centre_reg, radius, axis_reg`, skips when the centre's view depth is under `0x80`, and fills the screen conic of a disc of that radius whose normal is `regs[centre] − regs[axis]`; no branch depends on the normal's sign. `OP_VEC` (`0x004B`) has no slot: `CS:0x004B` is image `0x828B`, inside slot `0x0048`'s patch store, whose bytes there start `FE F4`, an undefined encoding. Corpus walk: 2,425 unique models; type 0 2,192 steps, type 2 320, type 4 152, type 8 57, `SPHERE` 1,584, `PERFDISK` 2,531, type 6 and `VEC` none. The icosahedron `vm.rs` emits for `SPHERE` had all 20 faces wound with their right-hand normals outward, counter-clockwise seen from outside, which the `FrontFace::Cw` pipeline culls, so only the far half drew. The stock-triangle winding tally was split close to evenly (walls 5,990 / 6,583), so it says nothing about a model-wide convention.
- **Verdict**: adopted: type 8 corners 1 and 3 swapped back, type 6 reads no operand, sphere faces reversed, each with a unit test. `PERFDISK` drawing nothing and type 6's registers are recorded as open.
- **Lives in**: [`sod-vm.md` § 8.8](../../../research/playone-exe/sod-vm.md#88-model-frame-the-other-generators).

## 2026-11-11: the generator fixes scored on lavapipe

- **Question**: Do the type 8 corner swap, the type 6 operand change and the sphere winding move parity on the reference films?
- **Method**: `mise run parity -- --films ctry,intro` on lavapipe in a cloud session, at `cbae8dc` (before) and `1878ac2` (with the fixes).
- **Result**: CTRY 0.8967 → 0.8967, INTRO 0.8339 → 0.8344 (`mean_ssim_scored`); IoU (0.9897, 0.9856), index agreement (0.901, 0.831) and scored frames (114, 209) unchanged. `[Bounded Observation]`, lavapipe only ([`lavapipe.md`](../../../research/parity/lavapipe.md)).
- **Verdict**: no measurable change: INTRO's +0.0005 is under the 0.002 floor. The fixes stand on the handler reads, not on a score; a GPU run has not been made.
