# Journal: OP_ANIMATE selectors and tests

## 2026-11-11: which bank words and tests OP_ANIMATE needs

- **Question**: Which bank selectors do the corpus's `OP_ANIMATE` shapes use besides `0x10` and `0x16`, and do the handler's register-flag test (`0xA9E9`) and the `SIF_ANIMATES` test (`0x3EF8`) change what a film draws?
- **Method**: Static, `mise run disasm`, `mise run xref` and `mise run vm-handler` over the unpacked unpatched image, at `dbfd0ed`. The census: a throwaway `eprintln!` in the `OP_ANIMATE` arm and the census model loop, run through `mise run sod-census` (not committed), tallying every operand set of every unique corpus model.
- **Result**:
  - 92 operand sets: selector `0x10` 72 (60 with one frame, 11 with the four `SMOKE.BIN` frames, one with `0x7E49`'s eight), selector `0` 12 (all one frame), selector `0x16` 8 (`EXP1`..`EXP8`, 12 frames). No shape uses `0x12`, `0x14`, `0x18` or `0x1A`. With one frame `(1 × word) >> 16` is 0 whatever the word, so no multi-frame stock table reads a word the scene reads as 0.
  - The register flag `+0x0A` is the clip outcode the projector at `[work:0x8082]` stores when it projects a register (`0x1AFA`, image `0x9D3A`): bit 0 when the depth `z + work:0x8088` is at most 0, bits 1 and 2 when `x >= z` or `x < -z`, bits 3 and 4 for `y`. The other projector (`0x1AB1`, image `0x9CF1`) stores 0. The object-entry routine `0x9100` picks between them at `0x914F` and `0x9167` after a bounding test (`0x9126..0x914D`), so an object inside the frustum takes the zero-flag path. `OP_ANIMATE` reads `+6`/`+8` as the screen point (`0xAA23..0xAA27`), so the register was projected first.
  - `SIF_ANIMATES` is the gate on the destination record's flag byte (`test byte [di + 1], 0x20` at `0x3EF8`). The slot player keeps `slot.animate` across keys and reads a new word only from an `interp` op whose slot has the flag (`flm/player.rs`), so a slot without the flag holds its last word, as `PLAYONE`'s record does. The held word is the last key's; `PLAYONE`'s record may hold the last interpolated step instead (`[Hypothesis]`, the `0x39AE` snapshot was not read for it).
- **Trial**: the register-flag test as a camera-space check on each sprite's centre in `scene.rs` (`z <= 0`, `|x| >= z` or `|y| >= z` with the lens-zoomed view, [`lod.md`](../../../research/playone-exe/lod.md) § 2.2, so 256 raster pixels from the screen centre on both axes). Evidence-backed track, image `0xA9E9` and `0x9D3A`. `mise run parity` on all seven films, an uncommitted tree on `dbfd0ed`: `ctry` 0.8996, `intro` 0.8418, `land` 0.8654, `balloon` 0.8030, `traintnl` 0.8518, `bomb` 0.8101, `location` 0.8068; every film within 0.0000001 of its pinned `expected.gpu` score, IoU the same.
- **Verdict**: not adopted (control): no film rises, so no scored frame changes (a sprite centre outside the frustum can exist and be off-screen anyway), and the adoption rule reverts a change that moves nothing. The check also decides from the authored camera only, so a free camera would drop sprites it sees. Selectors `0x12`..`0x1A` are deferred, unused by the corpus; the `SIF_ANIMATES` test needs no code.
- **Lives in**: [`sod-animate.md`](../../../research/playone-exe/sod-animate.md) §§ 1, 2 and 4, Open questions.
