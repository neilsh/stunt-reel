# Journal: relit actor vertex rewrites on lavapipe

## 2026-11-18: The rewrite's cost on the cloud's lavapipe

- **Question**: does a cloud session's lavapipe show the relit-vertex rewrite's cost that mesa-dist-win 25.2.8 shows on the RTX 4070 laptop (INTRO 12.5 s without, 23.9 s with; [#474 journal](../474_actor-light/journal.md#2026-11-16-what-relighting-actors-costs-a-render))? If so, #629 could be profiled and fixed in a cloud session.
- **Method**: `main` at `56a530d` (`crates` tree `71486d7`), release `stuntreel --headless` on `INTRO.FLM` with the pinned `INTRO.ALL`, every tick (3,823), `--width 320 --height 200 --viewport-rows 185 --software-only`. The machine was a cloud session: Ubuntu's Mesa 25.2.8 (`llvmpipe (LLVM 20.1.2, 256 bits)`) on 4 vCPUs (Intel Xeon @ 2.10 GHz). Each run was timed end to end, one at a time. The rewrite-skipped variant was a temporary probe, not committed: an environment switch that makes `GpuModel::rewrite_vertices` return `true` after its size check and before the chunk writes. That is #474's variant (c), which draws stale colours.
- **Result**: with the rewrite, 147.4 s and 129.5 s, with byte-identical `frames.zst`. With the rewrite skipped, 133.7 s, and `frames.zst` differs, as stale colours should. mesa-dist-win's rewrite cost (23.9 − 12.5 = 11.4 s) is smaller than the 17.9 s between the two identical runs here. The whole render takes 5 to 11 times mesa-dist-win's on this machine (129.5 s against 23.9 s with the rewrite; 133.7 s against 12.5 s without it). `[Bounded Observation]`: one film, three runs here and one run each in #474.
- **Verdict**: rejected as a cloud measurement. The rewrite's cost cannot be told apart from run-to-run spread on this machine, so #629 stays `local-only`: its before-and-after timing needs mesa-dist-win. This does not show whether the cost exists on Ubuntu's build, only that a cloud session cannot resolve it.
