# Retro: the cloud-assets pin check and the stack merge (2026-11-08)

Status: decisions agreed on 2026-11-08; R1 to R4 land in the pull request that adds this note. Source: the retrospective of the 2026-11-08 cloud session that verified #302's pin files before it merged, then tried to merge the #302/#303 stack. This note is the decision record and landing log, as [retro-2026-11-07.md](../retro/retro-2026-11-07.md) was for its session.

## 1. What happened

- The check passed. The startup hook replaced all four archive folders that held no `.cloud-assets-pin`; a second fetch skipped all four as holding their pin; `RES/MUSIC1.XMA` and `MUSIC2.XMA` were present; and `mise run parity` printed seven lines whose `scored` counts, IoU and SSIM equalled the previous cloud run's.
- The friction, in the order the decisions below answer it:
  1. The session started on its own branch at `c27940e`, the fix itself, so the startup hook did the migration. The brief's step 1 then reran the hook, which truncated `/tmp/cloud-session-start.log`; the `replaced` lines survived only because the session copied the log first.
  2. The run tested #302 at `c27940e`, but #302 was rebased to `44a795a` before merging. The session diffed the two before merging (comments and links only), and #302's Evidence still named `c27940e`.
  3. The merge failed twice: GitHub's REST merge endpoint answered 403 for a stacked PR, and auto-merge refused one. Nothing in the docs said so; the owner merged with `gh stack merge`.
  4. Seven-film `parity` took 177 s on lavapipe, against 24 s on the owner's GPU, and nothing recorded the cloud figure.
  5. Every `uv` call warned that `UV_NATIVE_TLS` is deprecated.

## 3. Rejected

- **R1 alternatives:** one log file per run (the path in the hook's line and the docs changes, and files pile up), and a brief-only rule to read the startup log before rerunning (every brief must remember it).
- **R2 as a tool** comparing the SHA in a PR's Evidence with its head: new code to parse PR bodies, for a case seen once.
- **R3 by upgrading `gh`** in the cloud setup: apt's `gh` is older than the image's, the newer builds' hosts are refused, and the proxy refuses GraphQL whatever the version, so a newer `gh` still could not merge a stack.
- **R3 as a new page for the new facts only:** cloud setup would then live in two files.
- **The move as its own pull request** stacked under the new facts: one more review round and a stack the owner merges by hand. Two commits in one pull request, merged without squashing, keep the move reviewable with `git diff --color-moved` and traceable with `git blame -C`.
- **A row for the new page in AGENTS.md:** it took the file over its 8 KB budget; `harness-setup.md`'s pointer routes there.
