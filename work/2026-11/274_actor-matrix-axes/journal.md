# Journal: actor matrix axes

## 2026-11-09: the actor matrix builder 0x04E5 read statically

- **Question**: In what order and about which axes does `PLAYONE.EXE`'s actor matrix builder `0824:04E5` compose the slot angle words `+0x10`, `+0x12`, `+0x14`, and does our `rotation_quat_dos` or FreeFlight's `sifilm.cpp` reading match it ([#274](https://github.com/neilsh/stunt-reel/issues/274))?
- **Method**: `mise run disasm` over the actor entry `0x1CFB..0x1D60`, the builder (image `0x8725..0x8811`), the 3×3 product `0824:060A` (image `0x884A`), the transpose copy `0824:0681` (image `0x88C1`), the row transform `0824:071D` (image `0x895D` → `0x88FB`), the view setup `0x1260..0x12DC` and the `OP_IPG` cube transform (image `0xB275..0xB2DE`), at `324c00f5`. The sine tables `work:0x19AA` and `work:0x21AA` read from the load image `build/re/playone.img` (image `0x176EA`, `0x17EEA`). The builder's nine products were written out by hand and compared numerically against `quat_from_euler(w2, -w1, w0)` (our `rotation_quat_dos`) and against FreeFlight's `Rx(w1) * Ry(w0) * Rz(w2)` over 200 random angle triples in a scratch NumPy script.
- **Result**: `0x1D14..0x1D20` load `BX = [+0x10]` (`w0`), `BP = [+0x12]` (`w1`), `SI = [+0x14]` (`w2`). The builder indexes 4096-entry tables with `word >> 4`; `work:0x19AA` is sine (0, 23170, 32767 at indices 0, 512, 1024) and `work:0x21AA` cosine. With `s`, `c` the sine and cosine of `a = w0`, `b = w1`, `c = w2`, it stores rows `(ca·cc − sa·sb·sc, −(sa·cc + ca·sb·sc), −sc·cb)`, `(sa·cb, ca·cb, −sb)`, `(sa·sb·cc + ca·sc, ca·sb·cc − sa·sc, cc·cb)`, which is `Ry(−w2) · Rx(w1) · Rz(w0)`. `0x060A` forms `view · R` with the view on the left, and the `OP_IPG` transform sums the products of row 0 with the input vector, so vertices transform as column vectors, `p_view = V · R · p`. The view setup builds the camera's matrix with the same builder and transposes it (`0x0681`) into `V`. Our `rotation_quat_dos` equals the builder to rounding (maximum element difference 0 in float64); FreeFlight's reading differs by up to 1.98 and turns `w0` about Y and `w2` about Z, the reverse of the builder, under every sign choice. The actor light (`0x1D36..0x1D44`) is transformed by `R` alone through the row transform, that is `R · L`, not `Rᵀ · L`.
- **Verdict**: control. Our builder already matches; a test pins it (`test_dos_rotation_matches_playone_actor_matrix_builder`). FreeFlight's axis assignment is rejected.
