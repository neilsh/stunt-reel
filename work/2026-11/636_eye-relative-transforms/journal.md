## 2026-11-16: Eye-relative transforms on both backends

- **Question**: whether computing each draw's `translate(-eye) * model` in f64 on the CPU, with a camera uniform that carries rotation and projection only, makes lavapipe and the GPU break the near-coplanar depth ties of [`lavapipe.md`](../../../research/parity/lavapipe.md) section 5 the same way, and what it does to GPU parity (`lavapipe.md` open question 1, #636).
- **Method**: branch `neilsh/636-eye-relative`, first on `origin/main` `3a7afb76` (commit `3a1207b4`, `crates` tree `73f4494`), then rebased onto `857f80a8`, which brought #630's actor lighting (commit `f6d57c9d`, `crates` tree `fb6474f`): `eye_relative_matrix` in `camera.rs` rounds `translate(-eye) * model` to f32 once; every per-draw uniform (props, actors, shadows, sprites, and now the world, whose matrix was the identity) carries it; `CameraUniform` carries `rotation_proj` (the view without its translation, then the projection) and its inverse; the sky ray is the inverse's far-plane point, with no `camera_pos` subtracted. Before: the coordinator's renders of `origin/main` on the same machine (`build/parity/main-3a7afb7/{gpu,lavapipe}` and `main-857f80a/gpu` in the `local-gpu-unattended` workspace). The residue figures below compare `3a7afb76` with `3a1207b4`; the scores compare `857f80a8` with `f6d57c9d`. After, on each tree: `mise run parity` on the RTX 4070 laptop, then `mise run parity -- --software-only --no-build` with `VK_DRIVER_FILES` naming only the mesa-dist-win 25.2.8 ICD (`llvmpipe (LLVM 21.1.7, 256 bits)` in every store). Residue: each film's index planes read from the two stores of one tree (`RenderStore.frame`) and compared pixel by pixel over every tick both hold, GPU against lavapipe, by a one-off script. Single ticks LAND 227 and BOMB 1910 rendered first with `mise run frame`, on each backend. Scores: `mise run judge -- <main gpu report> <branch gpu report> --track heuristic`.
