# Journal: two-vertex polygons

## 2026-11-11: the two-vertex polygon read statically

- **Question**: What does `PLAYONE` do with a `POLYZ` or `GVPOLY16` of two vertices, a line or nothing, and does stepping past it in `vm.rs` change `CTRY` or `INTRO` ([#393](https://github.com/neilsh/stunt-reel/issues/393))?
- **Method**: The unpacked image (`mise run unlzexe`) read with `mise run disasm`: the `POLYZ` handler `0x9B78`, `0x9100`'s writes of `[0x8080]`, the edge builders at `0xC9D4` and `0xC50E` (VM offsets `0x4794`, `0x42CE`), the gateway `0x8010`, and the driver vector table at `DS:0x10A4` for the slot `[0x2246]` (`0x7571`) and the Gouraud filler `0x75DB`. No live trace and no capture. Then `vm.rs` changed to emit `line_polygons` for a count of 2 (`OP_POLYZ`, `OP_GVPOLY`, `OP_GVPOLY16`), `mise run sod-census -- --format markdown`, and `mise run parity -- --films ctry,intro` on `origin/main` and on the change, same machine.
- **Result**: `0x9B78` has no count test. The edge builder is right for two vertices and wraps `CX` for fewer than two. Both edge walks of a two-vertex polygon measure the same segment, and the filler's spans are inclusive, so the polygon is a thin line: one pixel per row for steep edges and `GVPOLY`, a connected run for shallow `POLYZ` edges, whose two walks start half a step apart (read, not traced). The census went from 3,654 to 3,661 clean unique models and from 35 to 28 stepping over an opcode; groups B to D (7 models) are gone, group A (28 models, `OP_ANIMATE`) is unchanged. `CTRY` 0.8973 and `INTRO` 0.8344 before and after (identical to four places; per-film IoU 0.9897 and 0.9856), so no `references.toml` table changes. No parity reference places a shape of groups B to D.
- **Verdict**: adopted. `vm.rs` draws the line as a ribbon of world width `0.03 m` with the polygon's colour (the mean shade level for `GVPOLY`), a stand-in for the thin screen line.
