- **Routing.** No Sonnet implementer reported BLOCKED or needed an Opus re-dispatch. The Opus final review was the only gate to catch the critical defect below. The browser look ran in the build session, as the plan's fallback allowed, and its root-cause diagnosis went straight into the fix brief.
- **Waste.**
  1. The planning session spent 16 turns, 3.1M cache reads at about 190k tokens of context, relaying the build session's progress; 6 of those turns re-ran `git log` on commits the build session had already checked.
  2. The Haiku implementer armed 8 monitors in under 30 s while `mise run check` ran in the background. The leftovers woke it after its report, so it reported four times; the extra reports cost 3 no-op turns in the build session and 2 in the planning session.
  3. The build session spent 4 turns on files that only looked modified (line-ending noise).
- **Defects and the earliest gate that could have caught them.** The spec and plan reviews found what they should: Dependabot named where the repo uses Renovate, the gate classes, wrong `NOTICE.md` wording, the CLI's place, and three blocking faults in the plan's tests and output rules. The claim that `site/**` runs the full gate survived the second spec review into the plan, where the plan review flagged it again. Three of the four defects found later were wording the plan prescribed:

## 2. Decisions

| # | Decision | Where it lives |
|---|---|---|
| R1 | A subagent runs the gate in the foreground and stops any background job or monitor before it reports. Five distinct subagents in this repository since 2026-10-30, this one included, were re-prompted to report and reported three or more times; the cause was checked only for this one. | [harness.md](../../../docs/harness.md#policy-any-agent) |
| R2 | A session that hands the rest of its work to a session it starts answers that session's progress notes in one line with no tool calls, and checks the result once, at the end. Seventeen other parent sessions in this repository since 2026-10-31 received more than three such notes. | [harness.md](../../../docs/harness.md#desktop-app-auto-fix-and-isolated-subagents) |
| R3 | Recorded only: a plan that spells out code or prose wording can carry the defect itself, and its review should test that wording against the real notes. First seen here, so no rule. | this note |

## 3. Rejected

- **Haiku work moved to Sonnet:** Task 5's commit was correct, and its waste came from the leftover monitors that R1 covers.
- **Compacting the planning session before starting the build session:** it would have about halved each relay turn, but needs the user to remember a step; R2 needs none.
- **A check for plan-prescribed defects:** one occurrence.
- **Changing Policy's "a fix wave goes straight to the gate":** the build session re-reviewed its fix wave because the wave edited `research/README.md`, which [AGENTS.md](../../../AGENTS.md#committing) item 5 sends to a fresh reviewer. Item 5 governs; the overlap was seen once.
