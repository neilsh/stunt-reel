# Markdown breaks lines at sentences: spec

Decided with the owner on 2026-11-18, issue [#712](https://github.com/neilsh/stunt-reel/issues/712).
The evidence behind each decision is in [`journal.md`](journal.md).

## Problem

The repository's Markdown is wrapped two ways.
At `d4e01df` (2026-11-18), 158 tracked Markdown files kept each paragraph on one line and 103 hard-wrapped near 100 columns; the rest were too short to tell.
Of the 129 files the reflow covers, 12 were hard-wrapped.
In the first, editing one sentence rewrites the paragraph's whole line, so a diff, a review comment and `git blame` cover the whole paragraph.
In the second, an edit reflows the lines after it.
Either way, parallel branches that touch the same paragraph conflict; separate lines make that rarer, though git still conflicts on edits to adjacent lines.

## Decisions

1. **One sentence per line.**
   A long sentence may also break after a clause.
   No line breaks inside a link, a code span or inline math, and a `_Source:` line keeps its links.
   Tables, headings, front matter and fenced blocks are left as they are, and a GitHub alert's marker (`> [!NOTE]`) keeps its own line.
2. **Guidance, not a check.**
   The rule lives in [`docs/development.md`](../../../docs/development.md), with a one-line pointer in `AGENTS.md` and the reasoning in a new ADR.
   No lint task enforces it.
3. **Scope.**
   It applies to evergreen Markdown, to `work/` folders created after the guidance lands, and to new ADRs.
   It does not apply to existing `work/` folders (dated records, frozen once their work lands) or to accepted ADRs (immutable, [`work/README.md`](../../README.md#the-one-rule)).
   It does not apply to text sent to GitHub as an issue, pull request or comment body, where GitHub renders each newline as a line break.
4. **One reflow.**
   The existing evergreen files are reflowed once by a script that is run once and not kept as a task, in a pull request that holds nothing else.
   Its squash commit goes in [`.git-blame-ignore-revs`](../../../.git-blame-ignore-revs).
5. **The reflow is checked mechanically and read by a reviewer.**
   Every reflowed file must render to the same CommonMark HTML as before, apart from whitespace.
   The link and code-span regexes, which stop at a line end, must find no fewer matches than in the old text with each paragraph joined onto one line: the old text undercounts where a hard wrap already split a span.
   CommonMark does not render GitHub's alerts, so the script keeps their marker lines by rule.
   A fresh reviewer also spot-checks the source for splits that render the same but read badly.
   The commit body records both in its `Fresh-review:` trailer.
6. **Sequenced after other docs work.**
   The reflow runs only when no other branch holds unmerged evergreen Markdown changes, or the owner says to go ahead anyway.

## Reflow scope

All tracked `*.md` files except:

- `work/**` (frozen records; new folders follow the guidance as they are written),
- `docs/adr/**` (accepted ADRs are immutable),
- `tests/fixtures/**` (byte-exact test inputs),
- `corpus/**` (`AGENTS.md` § Committing forbids staging any file there),
- `research/MAP.md` (generated by `mise run knowledge-map`),
- `.github/pull_request_template.md` (its text becomes a PR body, where newlines render as breaks).

## Not in scope

- A lint rule or formatter for line breaks.
- Clause breaks: the script makes none; authors may add them by hand.
- Rust `///` and Python docstrings.
