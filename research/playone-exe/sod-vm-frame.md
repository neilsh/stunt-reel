# `PLAYONE.EXE`: Per-Frame Routine and Scene Composition

## 9. Per-Frame Routine and Scene Composition

`[Supported Inference]`, static. The per-frame routine at `0x0EE9` (entered from `0x4A35` with `BX = 0x4888`, the snapshot copy of the film state made at `0x39B0`) builds the sun vector (`0x196C`), sets the view matrix (`0x11FC`), makes one 3D scene draw through `0x824:0x0A05`, then draws the credits string at `+0xFE` with `0x58BD`. There is no second view or window pass, so a scene the evaluator does not place has no extra layer to supply it.

`DS:0x2275`, which selects `0x824:0x07DC` with `AX = 0xE8`, `CX = 0xD0`, is a video-mode flag set next to an `int 10h` mode change (`0x6E1B`, `0x737B`), not a window compositor. The window in the `COL3-2.FLM` reference is therefore part of the one scene, not a composited inset.

_Found 2026-10-22 at `ff274e7`; see the [parity log](../../work/2026-10/parity-log/log.md)._

**The credits text.** `[Established]`, static, and pixel-exact on the `INTRO.FLM` title cards of two captures ([`pfont.md` § 3.2](../formats/auxiliary/pfont.md#32-drawing-the-credits)). After the scene, `0x0F7B` skips the text when its first byte at `state + 0xFE` is negative, measures each line with `0x58D0` (the sum of `PFONT.BIN` widths at `DS:0x4F02`), centres it in the clip rectangle at `DS:0x2294..0x229A` as `left + ((right - left - width) >> 1)`, puts line 1 at `top + ((bottom - top - 28) >> 1)` and line 2 twenty rows lower (skipped when empty), and calls `0x58BD` with colour `0xFF`. `0x58BD` draws the string through the text driver slot `[0x225A]` twice: at `x + 1` in colour 0, then at `x` in the given colour, so the shadow lies under the ink. The font layout and the whole rule are in [`pfont.md`](../formats/auxiliary/pfont.md); the renderer draws it over offscreen pages ([`credits.rs`](../../crates/stunt-core/src/credits.rs)).

### 9.1 The Actor Shadow Draw

`[Established]` for the instruction sequences and the `work:0x806C` readers and writer listed here (disassembled, not run); `[Hypothesis]` for what they draw at run time (the shadow is the actor flattened onto the plane and filled in index 0: no live check, no render scored against the capture). Static, read from `build/re/playone.img` (2026-11-05, [#99](https://github.com/neilsh/stunt-reel/issues/99)); nothing observed live. The scene walk `0x1DD5` loops over the film's slots (list at `state + 0x2E`, count at `state + 0x1E`) at `0x1E07..0x1E3A`. For each slot it skips unless the flag byte `[si+1]` has bit 1 (draw) and bit 0 (exists) and the shape word `[si+2]` is nonzero, queues the actor with `0x1A90` (not for the slot equal to `[0x22DE]`, the view camera's, `0x1E26`; that skip leaves the shadow test below, so a view slot with draw, exists and shadow set and a shape still queues its shadow: `[Supported Inference]`, since 160 corpus films view from such a slot (223 film, slot and flags cases, slot 0 in 144 of them, flags `0x1F` in 186), while the `INTRO.FLM` view slots read live, 1 and 4, have flags `0x19` and shape 0, [`film-segments.md`](../parity/film-segments.md#21-held-sand-shots-at-ticks-2690-2850) § 2.1), and when `[si+1]` bit 2 is set also calls `0x19FC` at `0x1E35`. Those three bits are `SIF_DRAW`, `SIF_EXISTS` and `SIF_SHADOW` ([`flm.md`](../formats/flm.md#32-object-type-flags-type_flags-u8)): the create handler `0x3CF2` stores the create's `type_flags` byte verbatim at slot `+1` (`0x3CFD`, `[Established]`, static).

| Image offset | Role |
|---|---|
| `0x19FC` | Shadow queue. Takes the height from slot `+0x20/+0x22` when `+0x22` is nonzero. Otherwise reads the plane through the pointer at slot `+0x1E` (`a`, `b`, `c` at `+0`, `+2`, `+4`; 32-bit `D` at `+6`) and solves `y = (D - a*x - c*z) / b` at the actor's x (`+4/+6`) and z (`+0xC/+0xE`); a null pointer gives y = 0 (`0x1A12`). Then it transforms that point, looks up the slot's own shape (`[si+2]`, `0x4C41`), culls (`0x1B0C`) and queues it at `0x1AD8`. |
| `0x1A90` | Actor queue: the same, at the actor's own y (`+8/+0xA`), with `or al, 0x80` at `0x1AD6`. The shadow entry skips that `or`, so the operation is skipped; whether the resulting bit `0x80` is set is inferred, not traced, because the byte it reads comes from byte 9 of the shape header, which is untraced (`[Supported Inference]`; see the sort row). |
| `0x1B88..0x1BFF` | Entry sort. Branches on bit `0x80` of byte `+0xF` (`0x1B9F`, `0x1BA5`), a binary-tree insertion (children at `[node]` and `[node+2]`) walked right subtree, node, left subtree by `0x1BE6`. At a node with the bit clear (a shadow) every new entry goes left, drawn after it; at a node with the bit set (an actor) a new shadow goes right, drawn before it, and a new actor goes by depth (`0x1BAB..0x1BC7`, the larger depth value right, a tie left). Given that bit clear on a shadow entry, every shadow is drawn before every actor, whatever their depths. `[Established]` (disassembled, not run) for the sort and walk. The bit's value on a shadow entry is `[Supported Inference]`: `0x19FC` enters `0x1A90`'s tail at `0x1AD8`, past the `or al, 0x80`, so byte `+0xF` is `al` as `0x1B0C` leaves it (`mov al,[es:9]` at `0x1B6C`, byte 9 of the shape's segment header); what that byte holds is not traced, and a shape with bit 7 set there would sort as an actor. Whether a larger depth value is farther is not read. |
| `0x1C00` | Draws one entry. Bit `0x80` set goes to `0x1CFB` (the actor, light as `R · L` on the non-stored-matrix path, see [`terrain-shade.md`](terrain-shade.md) section 4.2). Clear goes to `0x1C0D`: builds the rotation matrix (`0x04E5`, `work:0x80D2`), halves it, replaces the Y row (second triple, `work:0x80D8..0x80DC`) with `-(a*row0 + c*row2) / b` (`idiv` by the plane's `b`; a null plane pointer zeroes it, `0x1C4B`), combines with the view matrix (`0x060A`), sets `work:0x806C = 0xFF`, calls `0x1D5F` (which runs the display list through `0x9100`) and clears the byte. |

`work:0x806C` is read at least at `0x7FD2`, `0x7FFB`, `0x8015`, `0x8040`, `0x92B2`, `0x93C2`, `0x97B1`, `0x9896`, `0x995C`, `0x9A24`, `0x9EC5`, `0x9F29`, `0xA040`, `0xA05C` and `0xA9DC`. Nonzero changes the VM as follows, reader by reader (handler = the opcode's nine-byte slot `imm16 + 0x8240`, section 1). The far gateways, which are not opcodes: the line gateway `0x7FD2` loads `DI = 0` instead of `work:0x41EA` before driver slot `[0x2244]`; `0x7FFB` returns without calling driver slot `[0x2248]`, so the one-pixel draws that call it draw nothing: the radius-0 branch of `OP_SPHERE` (`0x0FC`, `0x9E21`) and of opcode `0x2D9` (`0xA476`), and all of opcode `0x2D0` (`0xA3FC`); the flat-polygon gateways `0x8010` (test at `0x8015`) and `0x8040` load `CX = 0` instead of `work:0x41E8` before driver slot `[0x2246]`. The polygon handlers take the flat branch (`call [0x8080]`, then `lcall 0:8010`) instead of the Gouraud filler: `GVPOLY` (`0x168`, `0x995C`) and `GVPOLY16` (`0x2BE`, `0x9A24`) then step over their shade words; opcodes `0x333` (handler `0x97AA`, test `0x97B1`) and `0x33C` (handler `0x988F`, test `0x9896`), which act only while `work:0x806B` is set (else `0x333` skips ten bytes and `0x33C` eight), go straight to the next opcode, with no shade words to step over. These skip their work: the normal builders `0x15F` (`0x92B2`) and `0x132` (`0x93C2`), which skip `4 + 6·count` bytes and do not rewrite their opcode word to the `0x156` handler as a first normal run does; `OP_DISC` (`0x105`, handler `0x9EBF`, test `0x9EC5`), which draws no disc in the shadow (`OP_SPHERE`'s fill at `0x9DF3`, opcode `0x2D9`'s at `0xA448` and opcode `0x252`'s span table do not test the mode, so they still draw, in index 0); `OP_PERFDISK` (`0x10E`, `0xA040`); `OP_ANIMATE` (`0x1F8`, `0xA9DC`); and the sliced discs `OP_DISCSL` (`0x25B`, `0x9F29`) and `OP_PERFDISCSL` (`0x264`, `0xA05C`). Outside shadow mode each sliced disc builds its plain op's span table (`0xD11D`; through `0xA08E` for the perforated disc) without filling it, stores its start at `work:0x423E + n` for a last operand `n` (the third for `OP_DISCSL`, the fourth for `OP_PERFDISCSL`) and moves the span arena pointer `work:0x1952` past it. It stores 0 there instead in shadow mode, and when the build fails: for `OP_DISCSL` when the centre register's flag byte is set (`0x9F36`), `work:0x4218` is 0 (`0x9F5E`) or `0xD11D` finds the disc off screen, for `OP_PERFDISCSL` when `0xA08E` sets carry (centre depth under `0x80`, the high-word tests at `0xA156`/`0xA1AB`, or off screen). Of the ops at `0xA47F..0xA517`, `0x276` and `0x27F` push and pop `work:0x1952`, `0x288` fills one entry through `0:8040` and skips a zero entry (`0xA498`), so a stored 0 draws nothing, and `0x291`..`0x2AC` combine entries. So in shadow mode every polygon is flat palette index 0, drawn from the actor's own shape flattened onto the ground plane. [`memory-map-vm.md`](memory-map-vm.md) listed `0x806C` as an `OP_ANIMATE` gate only; that is one of its readers. Its only writer found is `0x1CE7`/`0x1CF4`.

**Where the plane and height come from** (`[Established]`, static). The only writer of slot `+0x1E` and `+0x20/+0x22` is the probe `0x240A`, which `0x1463` calls (`0x4A17` runs it on the snapshot `0x4888` before the frame draw `0x0EE9`) for each slot with `SIF_MOVES`, a shape, and `SIF_DRAW` or byte `+0` bit 3. It zeroes `+0x1C`, `+0x1E` and `+0x22`, then walks the scenery tree through a second dispatch table, `DGROUP:0x584`. At a ground leaf (`0x2631`) it counts edge crossings of the leaf polygon (anchor `x` and `z`) against the slot's integer `x` and `z` and on an odd count stores the leaf's plane address (leaf `+4`) at `+0x1E` (`0x26BE`); later leaves in walk order overwrite it, and a slot over no leaf keeps 0, a shadow on `y = 0`. At an object node (`0x257A`) it walks the shape's collision boxes (header word `+0xA`; box words `+2/+4`, `+6/+8`, `+0xA/+0xC` are the `x`, `y` and `z` ranges, `0x3047`); a box with code 8 at `+0xE` stores the object's `y` plus the box's least `y`, its top in the `y`-down axes, at `+0x20/+0x22` (`0x2A5B..0x2A8F`), so the shadow lies on that box, still tilted by the `+0x1E` plane. A slot without `SIF_MOVES` is never probed: its fields keep what they held, zero in the load image's records (`DS:0x2B2A`, 2 × 40 of `0x5A` bytes), since allocation clears only bytes `+0` and `+1`.

**Straight down** (`[Established]`, static). Row 1 of `R` yields a vertex's world `y` offset (`R` row-major on column vectors, draw matrix `0x80C0 · R`, [`memory-map-main.md`](memory-map-main.md) `0x8725`, `0x884A`), so `0x1C0D`'s replacement keeps each vertex's world `x` and `z` offset and puts it on the plane parallel to the leaf's through the shadow point: a projection along world `y`.

**No altitude test in the draw path's setup** (`[Established]`, static). Nothing from `0x1E2F` through `0x19FC`, the cull `0x1B0C`, `0x1C0D` and `0x1D5F`'s setup reads the actor's own `y` (`+8/+0xA`); the display-list run inside `0x1D5F` (`0824:0EC0`) was not reread for it. The probe's tree walk does test `y` (cube nodes, `0x2547`): a slot above a node's range finds no leaf there, and with no height box the shadow goes on `y = 0`, not nowhere; whether that hides a shadow over raised ground is untested. The films' flag changes follow no one height (`[Bounded Observation]`): 827 re-creates in 129 corpus films change only `SIF_SHADOW` (435 set it, 392 clear it). 397 of them, in 55 films, have `SIF_DRAW` clear, so the walk skips them at `0x1E13`; of the 430 on drawn shapes, in 104 films, the 239 sets and the 191 clears have median stream `y` −4.30 and −4.72 and reach −8060 and −6034. Where the handbook's cutoff lives is open (section 10).
