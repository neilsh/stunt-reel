# Specification: .SPR Sprite Bitmap Format

## 1. Overview & File Identification

The `.SPR` format represents uncompressed 8-bit indexed raster billboard images and animation frames developed for *Stunt Island* (1992, Walt Disney Computer Software / The Assembly Line). The format was codified by Dave Palmowski (2001, Stunt Island Filmmakers Association / SIFA) with the release of the `SpriteMaker` suite (`PCX2SPR.EXE`, `MAKESPR.EXE`, and `DRAWSPRT.EXE`), enabling community filmmakers and modders to inject custom camera-facing billboard visual effects (explosions, smoke clouds, muzzle flashes, rocket flares, dynamic logos, and the Death Star easter egg) into the engine.

- **File Extension:** `.SPR`
- **Magic Bytes:** None. The file begins directly with two 16-bit little-endian unsigned integers representing horizontal pixel width and vertical pixel height.
- **Typical Container / Storage:** Packaged as binary entries (`bin file.spr`) inside custom `.RES` archives (e.g. `MYSPRITE.RES`) generated by `MAKERES.EXE`.
- **Byte Endianness:** Little-endian (standard x86 16-bit real mode).
- **Engine Lifecycle Role:**
  1. *Raster Texture Storage:* Contains raw 8-bit VGA Mode 13h palette indices formatted for rapid scanline blitting into the $320 \times 200$ VGA video buffer.
  2. *Procedural Billboard Binding:* Bound to procedural `.SOD` (display list) models compiled by `MAKESPR.EXE`. The `.SOD` model defines the spatial transform, billboard orientation vector, animation frame count, and resource indices, while the `.SPR` payload supplies the raw texel colors.
  3. *Dynamic Visual Effects:* Rendered as camera-facing billboards centered at the entity's 3D origin, with index `0` acting as a strict transparency key.

## 2. Header & Memory Layout

A `.SPR` file has an extremely compact binary structure consisting of a 4-byte resolution header, an uncompressed raster pixel array, and a 2-byte end-of-file trailer word. The executable layout is [`spr.ksy`](spr.ksy).

### 2.1 File Structure Diagram

```
+-------------------+-------------------+-----------------------------------------------+-------------------+
|    Width (u16)    |   Height (u16)    |        Pixel Data (Width * Height bytes)      |   Trailer (u16)   |
|   Offset 0..1     |   Offset 2..3     |        Offset 4 .. (4 + W * H - 1)            |      0x0000       |
+-------------------+-------------------+-----------------------------------------------+-------------------+
```

### 2.2 Field Definitions

| Offset (Hex) | Size (Bytes) | Type | Field Name | Description | Evidentiary Tier |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `0x0000`–`0x0001` | 2 | `u16` (LE) | `width` | Horizontal pixel resolution. Must be an even positive integer (`!(width % 2)`), typically square ($256$ or $500$). | `[Established]` |
| `0x0002`–`0x0003` | 2 | `u16` (LE) | `height` | Vertical pixel resolution. Typically equal to `width` ($256$ or $500$). | `[Established]` |
| `0x0004`..$\text{EOF}-2$ | $W \times H$ | `u8[]` | `pixel_data` | Contiguous row-major array of 8-bit Mode 13h palette indices (`0..=255`). | `[Established]` |
| $\text{EOF}-2$..$\text{EOF}$ | 2 | `u16` (LE) | `trailer` | Fixed end-of-file terminator word `0x0000`. | `[Established]` |

### 2.3 Strict File Size Formula

The exact file size of any valid `.SPR` file is governed by the invariant formula:

$$\text{FileSize}_{\text{SPR}} = (\text{Width} \times \text{Height}) + 6\text{ bytes}$$

Where:
- $+4\text{ bytes}$ is the 2-word dimension header (`width` + `height`).
- $+2\text{ bytes}$ is the terminal trailer word (`0x0000`).

## 3. Data Structures & Opcode Table

### 3.1 Pixel Payload & Row-Major Addressing

Pixel bytes are stored in standard raster scanline order, starting from the top-left corner $(0, 0)$ and proceeding horizontally row by row to the bottom-right corner $(W-1, H-1)$:

$$\text{ByteOffset}(x, y) = 4 + (y \times \text{Width}) + x$$

Each byte is an unsigned 8-bit integer representing an index into the active 256-color VGA Mode 13h palette.

### 3.2 Color Index 0 Transparency Key

- **Transparent Pixel:** Palette index `0x00` (`0`) is defined as unconditionally transparent. When rasterizing `.SPR` pixels into the VGA framebuffer or modern render target, texels with index `0` are discarded (transparent keying / alpha mask test `alpha = 0.0`), allowing background 3D scenery and skyboxes to show through without overdraw.
- **Opaque Pixels:** Palette indices `0x01` through `0xFF` (`1..=255`) represent visible, opaque surface colors.

### 3.3 Procedural `.SOD` Billboard Coupling

A `.SPR` bitmap is never rendered in isolation; it is referenced by a procedural `.SOD` (display list) model compiled by `MAKESPR.EXE`. The compiled `.SOD` binary (typically 48 bytes for single-frame billboards, such as `DETHSTAR.BIN`, `DSTAR2.BIN`, `MAC500.BIN`, `MINE.BIN`) contains the following bytecode sequence:

| Offset | Size (Bytes) | Value / Opcode | Symbolic Name | Function |
| :--- | :--- | :--- | :--- | :--- |
| `0x00`–`0x01` | 2 | `0x000C` | `OP_ID` | Standard SOD header identifier |
| `0x02`–`0x03` | 2 | `u16` | `bounding_size` | Model bounding sphere radius |
| `0x04`–`0x05` | 2 | `0x0000` | `y_offset` | Vertical ground offset |
| `0x06`–`0x07` | 2 | `u16` | `scale_factor` | Initial scale factor (commonly `4000` or `0x0FA0`) |
| `0x08`–`0x09` | 2 | `0x0000` | `collision` | Collision sphere descriptor |
| `0x0A`–`0x0B` | 2 | `0x0075` | `OP_VECTORS` | Subobject vector definition table |
| `0x0C`–`0x2B` | 32 | Bytecode stream | Billboard Transform | Billboard orientation opcodes constraining normal to face camera eye |
| `0x2C` | 1 | `u8` | `frame_index` | 0-based frame index within the target `.RES` archive |
| `0x2D` | 1 | `u8` | `res_archive_id` | Resource archive index ID containing the `.SPR` files |
| `0x2E`–`0x2F` | 2 | `0x0195` | `OP_END` / `OP_RETURN` | Bytecode termination sentinel |

### 3.4 Animation Frame Cycling

When multiple `.SPR` frames are bound to a dynamic billboard object, `MAKESPR.EXE` compiles an animation sequence table:
- The total duration of the animation cycle remains constant across simulation ticks.
- The display duration per frame is inversely proportional to the frame count:
  $$\Delta t_{\text{frame}} = \frac{T_{\text{cycle}}}{N_{\text{frames}}}$$
- The playback engine indexes frames cyclically:
  $$\text{current\_frame}(t) = \left\lfloor \frac{t}{\Delta t_{\text{frame}}} \right\rfloor \pmod{N_{\text{frames}}}$$

## 4. Architectural Invariants & Coordinate Mapping

### 4.1 VGA Mode 13h Palette Indexing (`[I3]`)

In conformance with Invariant `[I3]`, `.SPR` pixels store raw 8-bit palette indices (`0..=255`) rather than pre-baked RGB values.
- **Hardware Mapping:** Mode 13h DAC registers provide 6 bits per channel ($[0, 63]$), normalized to modern floating-point color via:
  $$C_{\text{linear}} = \left(\frac{C_{\text{6bit}}}{63.0}\right)^{2.2}$$
- **Time-of-Day Lighting:** Under non-noon lighting (dusk, sunset, night), pixel indices are passed through `.ALL` lighting lookup tables (`LIGHT.TAB`, $256 \times 32$ LUT), smoothly darkening the sprite in harmony with 3D polygon shading.
- **Preservation:** The Rust core transpiler and `stunt-render` pipeline preserve exact palette indices in GPU vertex and texture structures, executing palette lookup via a 1D/2D texture sampler.

### 4.2 Metric Coordinates & Billboard Centering (`[I1]`)

Per Invariant `[I1]`:
- Sprites are authored as symmetric planar rectangles centered at local coordinate $(0.0, 0.0, 0.0)$.
- The four quad corner vertices in local space span:
  $$v_0 = \left(-\frac{W}{2} s, +\frac{H}{2} s, 0\right), \quad v_1 = \left(+\frac{W}{2} s, +\frac{H}{2} s, 0\right)$$
  $$v_2 = \left(+\frac{W}{2} s, -\frac{H}{2} s, 0\right), \quad v_3 = \left(-\frac{W}{2} s, -\frac{H}{2} s, 0\right)$$
  Where $s$ is the metric world scale multiplier derived from the `.SOD` scale word.
- In camera-facing billboarding, the quad's normal vector $\mathbf{n}$ is dynamically aligned with the inverted camera view direction:
  $$\mathbf{n}_{\text{quad}} = \frac{\mathbf{P}_{\text{cam}} - \mathbf{P}_{\text{sprite}}}{\|\mathbf{P}_{\text{cam}} - \mathbf{P}_{\text{sprite}}\|}$$

### 4.3 Cleanroom Decal & Billboard Separation (`[I5]`)

Unlike coplanar decals which require normal displacement ($\epsilon = 0.001\text{ m}$) against underlying mesh faces (`[I5]`), `.SPR` billboards exist as standalone 3D volumetric proxies with distinct depth buffer writes and alpha testing.

## 6. Attribution & Provenance

The technical specifications and byte layouts for the `.SPR` format are synthesized from the following primary community research and tooling archives:

- **Dave Palmowski (2001):** Author of the `SpriteMaker` package, designer of `PCX2SPR.EXE`, `MAKESPR.EXE`, and author of the authoritative format manual (`corpus/si_archive/SITools/SpriteMaker/sprite.txt`, `corpus/si_archive/SITools/SpriteMaker/Dstar.txt`).
- **SIFA (Stunt Island Filmmakers Association):** Preservation of sprite creation toolsets, palette files (`si.pal`, `si.act`), and community sample sprites (`dethstar.spr`, `f0.spr`, `MACLOGO.SPR`).
- **Adrian Stephens (The Assembly Line, 1992):** Original Stunt Island assembly engine architecture and billboard display list mechanics.
- **StuntReel Teamwork Team (2026):** Mathematical validation of the $(W \times H) + 6$ byte formula across the corpus, integration with `Seam 3: SodModelIr`, and documentation of Mode 13h palette index preservation `[I3]`.
