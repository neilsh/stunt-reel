# Technical Reference Specification: Stunt Island `.ALL` Full-Scene Bundle Format

## 1. Overview & File Identification

The `.ALL` file format is *Stunt Island*'s self-contained scene and movie package container. Whereas `.RES` packages store static global asset libraries, a `.ALL` package is a consolidated bundle generated by the movie packaging utility `MAKEONE.EXE` to contain every runtime asset required to play back a specific film sequence or scene.

A `.ALL` archive bundles 3D models (`.SOD`), choreography timeline scripts (`.FLM`), 8-bit VGA master palettes (240-color master palette and 16-color highlight sub-palettes), scenery quadtree geometry tables, and digital audio waveform clips (`.VOC`).

## 2. Header & Memory Layout

A `.ALL` archive employs a flat directory header consisting of an item count followed by two parallel contiguous lookup arrays: an array of 16-bit Resource Identifiers (`ids`), followed immediately by an array of 32-bit file byte offsets (`offsets`). The offset table carries one more entry than there are chunks: the final entry is a sentinel equal to the file size in intact archives.

### 2.1 On-Disk Directory Layout (`# [FMT-ALL-CHUNKS]`)

The executable byte layout is [`all.ksy`](all.ksy): `num_chunk_ids: u2`, `chunk_ids: u2[num]`, then `num + 1` `u4` offsets, giving a `len_header` of `6 * num + 6` bytes with the final offset acting as an EOF sentinel. The schema is the single source for field widths, offsets and byte order; this section keeps only the corpus evidence and parser policy.

Corpus verification (`[Bounded Observation]`): across the 289 `.ALL` files in `corpus/si_archive/`, `offsets[0]` equals `len_header` in every file, and the sentinel equals the file size in 288 of 289. `Films/MultiFLM/UFOAct2/BRIEFING.ALL` points past EOF, consistent with a truncated archive rather than a different layout.

#### Chunk Bounds & Slicing
Payload data immediately follows the directory header in contiguous, non-overlapping slices:
- For chunk $i \in [0, \text{num}-1]$:
  $$\text{Payload } i = \text{data}[\text{offsets}[i] \dots \text{offsets}[i+1]]$$
- The final chunk ends at the sentinel $\text{offsets}[\text{num}]$, which equals $\text{file\_len}$ in intact archives.
- The on-disk table does include an EOF sentinel entry, mirroring `.RES`. `parse_all` reads the first `num` offsets and extends the final payload to EOF, which is equivalent whenever the sentinel matches the file size.

#### Directory Integrity Guardrails
1. **Header Boundary**: `offsets[0] >= len_header`. If `offsets[0] < len_header`, the offset points inside the header table, raising `VfsError::InvalidOffsetTable`.
2. **Buffer Bounds**: $\text{offsets}[i] \le \text{file\_len}$ for all $i$. An offset exceeding file length raises `VfsError::UnexpectedEof`.
3. **Monotonicity**: $\text{offsets}[i+1] \ge \text{offsets}[i]$ for all $i \in [0, \text{num}-1]$, including the sentinel. Inverted offsets raise `VfsError::InvalidOffsetTable`.

## 3. Data Structures & Opcode Table

### 3.1 Resource ID Partitioning

The 16-bit unsigned resource identifier (`id: u16`) partitions into distinct functional asset domains. These IDs allow the runtime engine to map numeric keys directly to asset types without file extension metadata:

| ID Range (Hex) | ID Range (Dec) | Asset Type / Engine Role | Internal Header Signature | Description |
| :---: | :---: | :--- | :---: | :--- |
| `0x0001`–`0x7FFF` | $1..32767$ | **3D Model Geometry (`.SOD`)** | `0x000C` (`b"\x0c\x00"`) | Procedural bytecode display-list geometry. This ID matches `shape_id` referenced in `.FLM`, `.SET`, and static scenery leaf nodes (`SP_LEAF`, opcode 10 in `SCENERY.scn`)! |
| `0x8000`–`0x803F` | $32768..32831$ | **16-Color Palette Ramps** | `0x0030` (`48` bytes) | 16-color RGB sub-palette or UI highlight ramp. Example: `0x801E` in `COLORS.ALL`. |
| `0x8040`–`0x80FF` | $32832..33023$ | **240-Color Master Palette** | `0x02D0` (`720` bytes) | Complete 240-color Mode 13h VGA master color table. Example: `0x8042` in `COLORS.ALL`. |
| `0x8100`–`0xBFFF` | $33024..49151$ | **Scenery / Map Data** | Variable | Scenery quadtree nodes (`.MAP`), terrain elevation grids, and collision tables. |
| `0xC000`–`0xCFFF` | $49152..53247$ | **Digital Sound Effects (`.VOC`)** | `0x02 0x01` / `0x02 0x00` | 8-bit unsigned PCM audio waveforms. Referenced directly by `arg2` in `.FLM` opcode `0x9C`! |
| *Special / Any* | *Any* | **Choreography Stream (`.FLM`)** | `b"FILM"` (`0x46, 0x49, 0x4C, 0x4D`) | Full film choreography script. Extracted as `"CHOREO.FLM"` in VFS. |

### 3.2 VGA Mode 13h Palette & 16-Level Shading Ramps (`[I3]`)

*Stunt Island*'s rendering engine operates in authentic 8-bit VGA Mode 13h ($320 \times 200$ resolution, 256 indexed colors). The full 256-color palette is divided into two primary chunks:
- **Base 240 Colors (Indices `0..239`):** Stored in Chunk ID `0x8042` (720 bytes, comprising 240 little-endian 8-bit RGB triplets).
- **Upper 16 Colors (Indices `240..255`):** Stored in Chunk ID `0x801E` (48 bytes, comprising 16 8-bit RGB triplets), providing UI widgets, text chrome, cockpit HUD elements, and pure green transparency keying (`#00ff00`).

#### 3.2.1 16-Color Group Organization & 32-Color Composite Shading Ramps
The 256 colors are organized into **16 functional groups of 16 contiguous colors each** ($16 \times 16 = 256$), documented in historical `shading.doc` and `si.pal`:

| Group ID | Palette Indices | Color Theme / Domain | Darkest Color | Brightest Color | Shading Ramp Behavior |
| :---: | :---: | :--- | :---: | :---: | :--- |
| **Group 0** | `0`–`15` | Monochrome / Deep Shadows | `0` (`#000000`) | `15` (`#837373`) | 16-level ambient shadow attenuation floor |
| **Group 1** | `16`–`31` | Deep Red / Crimson | `16` (`#3f0f1b`) | `31` (`#ff9fdf`) | 16-level red lighting / aircraft insignia ramp |
| **Group 2+3** | `32`–`63` | Neutral Gray & Pure White | `32` (`#534343`) | `63` (`#f7f7f7`) | **32-level composite ramp**: Aircraft fuselages, concrete runways, clouds |
| **Group 4+5** | `64`–`95` | Desert Tan & Sandstone | `64` (`#3f3723`) | `95` (`#ffdb8b`) | **32-level composite ramp**: Sand dunes, canyons, desert terrain |

### 3.3 Audio Sample Chunks (`0xC000`–`0xCFFF`)

Sound sample chunks contain raw 8-bit unsigned mono PCM audio clips digitized at typical Sound Blaster sample rates (e.g., 11,025 Hz or 8,000 Hz):
- **Resource ID Resolution:** When a `.FLM` choreography stream encounters opcode `0x9C` (`sound`), operand `arg2` specifies a 16-bit resource ID in the range `0xC000`–`0xCFFF`.
- **Runtime Binding:** The engine queries the loaded `.ALL` container for chunk `arg2`, obtaining the raw waveform bytes for playback through the Sound Blaster DSP without disk seeks.

### 3.4 Runtime Scene Reconstruction & Model Binding (`[Established]`)

During standalone playback in `PLAYONE.EXE` (and modern reconstruction in `stuntreel`), `.ALL` archives provide both the dynamic actor models and the static prop definitions for the island environment:
1. **Model Catalog**: Chunks with IDs in `0x0001`–`0x7FFF` (`MODEL_%04X.SOD`) form a local scene catalog.
2. **Dynamic Binding**: Actors evaluated in `.FLM` trajectory ticks bind to these models via `ActorTransform::shape_id`.
3. **Static Scenery Instantiation**: Simultaneously, the static scene graph (`SCENERY.scn`) resolves its `SP_LEAF` object IDs against this same catalog, allowing standalone films to reconstruct complete sets (hangars, towers, buildings, flora) alongside moving aircraft.

### 3.5 Entry Naming Policy (`[I8]`)

When `.ALL` chunks are unpacked into `VfsArchive`, entry filenames are normalized to uppercase 8.3 keys per Invariant `[I8]`:
- Payloads starting with `b"FILM"` are mapped to `"CHOREO.FLM"`.
- Payloads starting with `0x000C` are mapped to `format!("MODEL_{:04X}.SOD", id)`.
- All other chunks are mapped to `format!("RES_{:04X}.BIN", id)`.

## 4. Open Questions & Reverse Engineering Backlog

The following backlog documents open questions and investigations regarding the `.ALL` bundle format:

| ID | Topic / Investigation Area | Current Evidence & Finding | Evidentiary Tier | Recommended Handling in Engine |
| :--- | :--- | :--- | :---: | :--- |
| **Q-ALL-01** | Scenery Quadtree Nodes (`0x8100..0xBFFF`) | Chunks in this ID range contain quadtree bounding nodes (`SP_POS`, `SP_1NODE`) referenced in `simap.cpp`. Alignment with `SCENERY.BIN` remains under active research. | `[Supported Inference]` | Treat as raw binary chunks (`RES_{id}.BIN`) until quadtree parser is implemented. |
| **Q-ALL-02** | LZSS Sub-Chunk Compression | Milestone 2 cleanroom fixtures and retail film packages store raw uncompressed bytecode (`was_compressed = false`). Whether specific non-US CD-ROM releases used LZSS within `.ALL` is unverified. | `[Bounded Observation]` | Keep `was_compressed: false` default. Hook LZSS decompressor if compressed markers are found. |
| **Q-ALL-03** | Dynamic Sound Pre-Caching | Original engine loaded audio chunks directly into Sound Blaster DMA buffers at scene initialization. | `[Supported Inference]` | Store PCM audio buffers in memory; log playback events during Milestone 2. |
| **Q-ALL-04** | Duplicate Resource IDs in Container | If a malformed `.ALL` contains duplicate IDs, later entries overwrite earlier entries in `BTreeMap`. | `[Established]` | Safe behavior; duplicate IDs log a warning and overwrite deterministically. |
| **Q-ALL-05** | Standalone Movie Linker Internal Symbol Table | `MAKEONE.EXE` may have compiled an internal symbol hash map during film linking before stripping string names and writing raw numeric 16-bit IDs to the `.ALL` directory header. | `[Hypothesis]` | Modern engine indexes chunks directly by 16-bit numeric ID without requiring external symbol maps. |
